# Portfolio SEO audit — 21 November 2026

Site: https://atharav001.vercel.app/  
Repository: https://github.com/Atharav001/portfolio-3.0  
Method: [Claude SEO](https://github.com/AgriciDaniel/claude-seo) checklists and read-only scripts, local build inspection, live HTTP checks, and visual inspection of a generated case study. This is a technical and content audit, not a measurement of Google rankings.

## What SEO means here

Search engine optimization helps search services discover the portfolio, read its project pages, understand which page is the canonical version, and show useful titles and previews. It does not guarantee indexing, a ranking position, clicks, or AI citations. For this portfolio, the most important change was making project evidence available in normal HTML and at distinct URLs.

All nine sitemap URLs returned HTTP 200 after deployment. Every listed page had a matching self-referencing canonical URL. The eight generated project pages had no image without alt text in the live HTTP check. The Claude SEO parser found no invalid JSON-LD syntax on the sampled homepage and PreciCast page.

## What was implemented

1. **Crawlable homepage:** The production HTML includes a readable project summary before React runs. When JavaScript loads, the existing interactive portfolio replaces that fallback. Both versions describe the same work.
2. **Eight project pages:** Each case study has its own public `.html` URL, title, description, main heading, author, project image, approach, implementation, results or limits, source links, and related project links. Project titles on the interactive cards link to these pages; the existing overlay buttons still work.
3. **Discovery and canonicalization:** Build-generated sitemap and a robots file make the pages easier to discover. Each page identifies its preferred URL through a canonical tag. The sitemap omits `lastmod` because an accurate content-change date is not available for every case study.
4. **Structured data:** The JSON-LD describes the visible person, website, source-code projects, and navigation path. It avoids invented ratings, awards, publication dates, or review markup.
5. **Search/social previews:** The homepage description is more specific to the work. Each project page has its own Open Graph and X/Twitter title, description, and image.
6. **HTTP status cleanup:** Removed a blanket SPA rewrite so unknown paths return 404. The chat API route remains configured separately.
7. **Repeatable checks:** `npm run build` writes the static SEO output, and `npm run seo:check` checks page files, sitemap entries, canonical URLs, structured data parsing, links, and local assets.
8. **Optional agent-readable summary:** `llms.txt` gives a plain-text directory of the case studies. It is useful as a discovery convenience for systems that choose to read it; it is not a Google Search ranking factor.

## Next steps for the owner

1. In [Google Search Console](https://search.google.com/search-console/), verify ownership of `https://atharav001.vercel.app/`. If you later buy a custom domain, verify that domain and update all canonical and sitemap URLs when migrating.
2. Submit `https://atharav001.vercel.app/sitemap.xml` in Search Console. Use URL Inspection on the homepage and one or two case studies, especially PreciCast, to check Google's rendered page and indexing status.
3. Review Search Console's Pages, Performance, and Core Web Vitals reports after data appears. Indexing and traffic take time; sitemap submission does not guarantee either.
4. Use [PageSpeed Insights](https://pagespeed.web.dev/) on the homepage and a case study. Prioritize measured LCP, INP, or CLS problems rather than optimizing to a guessed score.
5. Keep project results, limitations, screenshots, repository links, and dates accurate. Publish a new case study when a project has distinct evidence worth sharing.
